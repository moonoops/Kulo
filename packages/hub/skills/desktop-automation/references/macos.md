# macOS Desktop (`darwin`)

Applies only when `kulo_desktop` reports `platform: "darwin"` on the target execution device.

- **Accessibility (AX) Permissions**: macOS Accessibility permission belongs to the specific app/process launching `agent-desktop`. If `status` reports `accessibility: denied` or `snapshot` fails with `PERM_DENIED`, close the session, report `state: "blocked"` (not `"ready"`), and direct the user to grant Accessibility for that device in **Kulo 设置 → 系统权限** (select the target Mac and start the setup guide) or in System Settings → Privacy & Security → Accessibility (if an updated dev build was previously listed, remove and re-add it)—never trigger OS permission dialogs automatically, and never request Screen Recording for semantic AX operations.
- **Observe-Verify Discipline**: An AX action returning success does not guarantee the UI state actually changed (e.g., Finder or Electron controls can acknowledge `AXPress` silently). Re-run `snapshot` on the same `app` after every action to confirm the result.
- **Ref Lifetime & Surfaces**: Refresh refs after app restarts, list reorders, sheets, alerts, popovers, or modal dialogs; refs captured behind an open sheet or menu are stale and will fail with `STALE_REF`. A regular app with no visible window returns `WINDOW_NOT_FOUND`.
- **Strict Boundaries**: Stay strictly within `kulo_desktop`'s semantic actions (`status` / `snapshot` / `click` / `type` / `set-value` / `scroll` / `wait` / `close`). Never fall back to physical mouse/keyboard simulation, raw CLI flags (`--headed`, `press`, `launch`), or AppleScript; hand unsupported steps back to the user.
